# Pitch Detection Bug Fix - Session Summary (2025-12-11)

## Bug Description

**Issue**: Pitch detection in pladdrr produced incorrect F0 values, causing significant errors in downstream analysis like tremor frequency calculation.

**Example**:
- **Expected tremor frequency**: 1.736 Hz (from Praat)
- **pladdrr result**: 4.999 Hz (188% error!)
- **Problem frames 4-9**: pladdrr detected F0 (120-137 Hz), Praat correctly marked unvoiced

## Root Cause

Praat's pitch detection functions expect `integer maxnCandidates` where `integer` is a Praat type defined as:
```cpp
using integer = intptr_t;  // 64-bit on modern systems
```

But pladdrr's C++ wrappers used:
```cpp
int max_candidates  // 32-bit
```

On 64-bit systems, this caused **parameter misalignment** - the Praat function received garbage values for `max_candidates` because it read 8 bytes while only 4 bytes were provided.

## Solution

**Cannot use Praat's `integer` type directly in Rcpp exports** (Rcpp code generation fails).

**Working approach**:
1. Keep R/Rcpp interface as `int` (Rcpp understands this)
2. Cast to `integer` when calling Praat functions

```cpp
// In sound_wrappers.cpp
// [[Rcpp::export(.sound_to_pitch)]]
Rcpp::XPtr<structPitch> sound_to_pitch(
    Rcpp::XPtr<structSound> sound,
    int max_candidates,  // ✓ Rcpp can handle
    ...
) {
    try {
        autoPitch pitch = Sound_to_Pitch(
            sound.get(),
            static_cast<integer>(max_candidates),  // ✓ Correct type to Praat
            ...
        );
        ...
    }
}
```
