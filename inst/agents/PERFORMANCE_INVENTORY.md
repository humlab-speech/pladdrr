# Performance Inventory (pladdrr)

> **v5.0.0 note — read this before acting on the tables below.** This file is a
> *static* inventory (which files contain SIMD or threading), regenerated by
> `tools/perf_inventory.sh`. It says nothing about whether any of it pays off.
> Headlines:
>
> - **First: verify the build.** `simd_info()$debug_build == TRUE` means the `.so`
>   was compiled without `NDEBUG` at `-O0` (the `devtools::load_all()` /
>   `pkgbuild::compile_dll()` flags, which a later `R CMD INSTALL` reuses instead
>   of recompiling). That alone costs **2.1–7.0x across every routine**. Fix with
>   `R CMD INSTALL --preclean .` before profiling. All pre-v4.9.22 numbers in this
>   project were taken on such a build.
> - **On a correct build, CPPS is at parity with the Praat 6.4.47 binary** — same
>   `Get CPPS` call, 0.95–1.08s vs 0.95–1.04s — and pladdrr wins 11 of 15
>   downstream plabench benchmarks. There is no further headroom that does not
>   change results.
> - **~84% of CPPS runtime is Praat's median-of-ninthers quickselect**
>   (`expandPartition`, `medianOfNinthers`, `adaptiveQuickselect`,
>   `NUMquantile_e`); the Siegel pairwise-division loop is only **~16%**. pocketfft,
>   cepstrogram creation and the parallelised smooth are each <1%. Optimising
>   anything but the median select is noise.
> - **Compiler flags are already optimal at CRAN's `-O2`.** `-O3`,
>   `-march=native` and `-fvisibility-inlines-hidden` each produce a
>   byte-identical object for `SlopeSelector.cpp` and are unmeasurable end to end.
>   Earlier "3–7x from `-O3 -march=native`" guidance was the debug-build penalty
>   misattributed; it has been retracted.
> - **The SIMD toggle moves whole-routine time by -1% to +6% on arm64.** SIMD pays
>   in the batch-statistics bridges (mean 4.1x, range 15.4x vs base R), not in
>   end-to-end analysis.
> - **Exception, the SlopeSelector kernels: default-off since v4.9.21.** They
>   vectorize the ~16% of `getSlope_Siegel` that is divides and leave the ~84%
>   that is `NUMquantile_e` untouched. Re-measured interleaved on a correct build
>   they are within noise — no longer the 1.7–2.4x *slowdown* seen on the debug
>   build, but still not a win. **Any future SIMD work on this fit must target
>   `NUMquantile_e`.**
> - **Threading has no headroom.** CPPS 1→10 threads is 8.42s → 1.55s (5.4x);
>   8 threads already gives 5.39x, so the M1 Pro's 2 efficiency cores add ~1%.
>   Praat's own efficiency on the same workload is 4.85 effective cores, below
>   pladdrr's — a dynamic scheduler is not worth adding.
> - **Stock CRAN builds reach SSE2 on x86_64 and NEON on arm64 — never AVX2 or
>   AVX-512.** No `-march=` (CRAN policy) and no runtime dispatch.
> - Six `*_simd.cpp` files listed in earlier revisions of this inventory were
>   deleted in v4.9.19 for having no referenced symbols.
> - `std::nth_element` in `getSlope_Siegel` was measured and **rejected**: bit-exact
>   but 25% slower than Praat's median-of-ninthers. See `PRAAT_MODIFICATIONS.md`.
