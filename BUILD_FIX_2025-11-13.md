# Build Fix - November 13, 2025

## Problem
Package build was failing with linker error:
```
symbol not found in flat namespace '__ZN11structRoots10v9_destroyEv'
Error: loading failed
```

## Root Cause
1. The Praat `Polynomial.cpp` source file calls `Polynomial_to_Roots()` in the `v_getExtrema()` method (line 159)
2. This creates a `Roots` object which requires the full Roots class implementation
3. The Praat source has `Roots.cpp.disabled` - it's not available
4. We provide stub implementations in `roots_stubs.cpp`, but were missing the required virtual method `v9_destroy()`

## Solution Applied
Modified `src/roots_stubs.cpp` to:

1. **Provide Thing_implement macro call** - Required for class linkage
2. **Implement v1_info() method** - Declared in Roots_def.h  
3. **Implement v9_destroy() method** - Required by Thing infrastructure even though it has a default implementation in structThing
4. **Remove return statements from error-throwing functions** - `Melder_throw` never returns, so `return autoRoots()` was causing unnecessary object construction

### Key Changes
- Added `void structRoots :: v9_destroy () noexcept` implementation that calls parent's v9_destroy()
- Removed `return autoRoots()` statements after `Melder_throw()` calls
- Kept error-throwing stubs for all Roots-related functions

## Impact
- **Minimal**: Roots functionality is not exposed to R users
- Polynomial extrema finding (which uses Roots internally) will throw an informative error if called
- Core package functionality remains intact
- All main analysis objects (Sound, Pitch, Formant, etc.) work normally

## Files Modified
- `src/roots_stubs.cpp` - Added v9_destroy() implementation, cleaned up stubs
