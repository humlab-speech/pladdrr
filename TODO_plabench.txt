⏺ No disk I/O is slowing down the VUV implementation.

  Findings:
  1. pladdrr works in-memory - no temp files created during pitch extraction
  2. TextGrid merge path adds ~14ms disk I/O, but benchmark doesn't use it (runs with textgrid_file=NULL)

  The 18x slowdown is purely computational overhead from:
  - R6 class method dispatch
  - R ↔ C data marshalling
  - pladdrr's architecture vs Parselmouth's direct pybind11 bindings

  The to_pitch_cc() cross-correlation algorithm itself is CPU-bound, not I/O-bound.
