# Build Fix: LPC Wrapper XPtr Conversion Issue
**Date**: 2025-11-29  
**Version**: 1.1.0 → 1.1.1  
**Status**: ✅ RESOLVED

## Issue Description

The package failed to build with compilation errors in `src/lpc_wrappers.cpp`:

```
lpc_wrappers.cpp:289:33: error: no viable conversion from 'SEXP' (aka 'SEXPREC *') to 'Rcpp::XPtr<structSound>'
  289 |         Rcpp::XPtr<structSound> sound_xptr = private_env.get("ptr");
      |                                 ^            ~~~~~~~~~~~~~~~~~~~~~~

lpc_wrappers.cpp:356:33: error: no viable conversion from 'SEXP' (aka 'SEXPREC *') to 'Rcpp::XPtr<structSound>'
  356 |         Rcpp::XPtr<structSound> sound_xptr = private_env.get("ptr");
      |                                 ^            ~~~~~~~~~~~~~~~~~~~~~~
```

The problem occurred in two LPC methods:
- `praat_lpc_sound_filter_inverse()` (line 289)
- `praat_lpc_sound_filter_inverse_with_filter_at_time()` (line 356)

## Root Cause

The issue was an **implicit conversion attempt** from `SEXP` to `Rcpp::XPtr<structSound>`. 

The `Rcpp::Environment::get()` method returns a `SEXP`, but the `XPtr` constructor is marked as `explicit`, meaning it cannot be used in implicit conversions. This is a type safety feature in Rcpp.

```cpp
// INCORRECT - implicit conversion not allowed
Rcpp::XPtr<structSound> sound_xptr = private_env.get("ptr");

// CORRECT - explicit construction required  
Rcpp::XPtr<structSound> sound_xptr(private_env.get("ptr"));
```

## Solution

Changed both occurrences from **copy initialization** to **direct initialization**:

### Line 289
```cpp
// Before
Rcpp::XPtr<structSound> sound_xptr = private_env.get("ptr");

// After
Rcpp::XPtr<structSound> sound_xptr(private_env.get("ptr"));
```

### Line 356
```cpp
// Before
Rcpp::XPtr<structSound> sound_xptr = private_env.get("ptr");

// After
Rcpp::XPtr<structSound> sound_xptr(private_env.get("ptr"));
```

## Technical Notes

This is a C++ initialization syntax issue:

1. **Copy initialization** (`T obj = expr;`): Requires implicit conversion if types don't match
2. **Direct initialization** (`T obj(expr);`): Allows explicit conversions

Rcpp's `XPtr` template uses `explicit` constructors to prevent accidental type conversions, which is a best practice for resource-managing types. The fix uses direct initialization to properly invoke the explicit constructor.

## Related Work

These methods were recently added as part of the LPC inverse filtering functionality (plotting gap analysis implementation). The conversion pattern is used correctly throughout the rest of the codebase - these two instances were simply overlooked.
